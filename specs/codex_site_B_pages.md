## 1. Build mode and the public gate (highest priority)
- `AIXON_BUILD` must be exactly `preview` or `public`. Missing or any other value → throw (fail closed). There is no default. Unit tests pass the mode explicitly to `loadGraph`.
- **Public** builds read the allow-list written by `tools/public_gate.py`: path `process.env.AIXON_PUBLIC_GATE || '.aixon/public-gate.json'`. Before using it, check with Node `crypto` that `graph_files` equals the graph paths being loaded and that every entry of `inputs` (graph files **and** the `*.mdx` files of the wiki dir) has the same sha256 as the current file, and that the set of wiki files is the same; otherwise throw `stale public gate: run python tools/public_gate.py`. Missing file → throw.
- Public visibility comes **only** from that file: entity ∈ `entities`, claim ∈ `claims`, wiki ∈ `wiki`, source ∈ `sources`. Anything else is not emitted anywhere: no page, no `graph.json` node or edge, no `node-index.json` entry, no sitemap URL, no mention in lists, coverage counts or search. Field hierarchy/membership edges only between public entities. Remove the `summary_by`-based `publicSummary` logic: a public entity's summary is approved by definition; a non-public entity does not exist in the public build.
- **Preview** builds show everything except that rejected/deprecated claims appear only on their own claim page (history), with badges.
- One module decides visibility for every page (`src/lib/graph/visibility.ts` or inside `index.ts`): `isVisible(kind, id)`, `wikiFor(entityId)` (collection + visibility), `visibleClaimsOf(entityId)`. Pages, ConceptLink, Cite, coverage, search and graph.json use only these.
- `<Cite claim>` to a claim that the build does not emit: number without link + "(검토 대기)". `<ConceptLink>` to an entity whose wiki is not emitted → entity page; to an entity not emitted at all → plain text (no dead link).
- Vitest (`tests/unit/graph.test.ts`, rewrite — the current tests assume a stand-in seed): inline temp YAML/MDX files (`fs.mkdtempSync`) + a hand-written gate JSON. Cases: unknown/missing `AIXON_BUILD` throws; missing gate throws; gate with a wrong input hash throws; public keeps exactly the gate's ids (an approved-looking claim not in the gate is dropped); preview drops rejected from lists but keeps its page; duplicate id throws; intro year = earliest INTRODUCES paper date; prerequisites grouped by `for_dimension`; `wikiFor` respects the build mode.

## 2. Badges and wording (ADR-022)
Never write "검증됨" alone. Claim badges are three separate facts:
1. **인용 확인(기계)** — `status` verified|disputed and `verification` present (tooltip: "인용문이 지정한 판의 원문에 있음을 기계로 확인. 인용이 관계를 뒷받침하는지는 사람 검토가 판단").
2. **사람 검토** — "승인: <by>, <at>" when `review.decision == approve` and `review.by` starts with `human:`; otherwise "검토 대기". (Freshness of the approval is enforced by `make validate`/G022; preview just shows the record.)
3. **공개** — shown only in public builds (everything there is public).
Status words: proposed "후보(미검증)", disputed "논쟁 중", rejected "기각됨", deprecated "폐기됨". Confidence as text (높음/보통/낮음).
