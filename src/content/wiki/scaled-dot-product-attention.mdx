<Section id="overview" level="intuition" title="개요와 직관">

문장 "그 동물은 길을 건너지 않았다, 왜냐하면 그것은 너무 피곤했기 때문이다"에서 "그것"이 무엇을 가리키는지 알려면, "그것"이라는 단어가 문장의 다른 단어들을 **얼마나 참고해야 하는지** 정해야 합니다. Scaled Dot-Product Attention은 이 "얼마나 참고할지"를 계산하는 방법입니다.

각 단어(토큰)는 세 가지 역할의 벡터를 가집니다.

- **query(질의)**: "나는 어떤 정보를 찾고 있나"
- **key(열쇠)**: "나는 이런 정보를 가지고 있다"는 표시
- **value(값)**: 실제로 넘겨줄 정보

query와 각 key가 얼마나 잘 맞는지 점수를 매기고, 점수를 확률처럼 바꾼 뒤, 그 비율대로 value들을 섞습니다. 결과는 "나에게 필요한 정보를 다른 토큰들에서 골라 섞은 벡터"입니다. Transformer 논문은 attention 함수를 "query와 key–value 쌍들을 출력으로 대응시키는 것이며, 출력은 value들의 가중합이고 가중치는 query와 각 key의 호환도로 정한다"고 정의합니다<Cite claim="clm:sdpa-is-a-attention" loc="§3.2" />.

<Callout kind="key">
한 줄 요약: **점수 = query·key, 가중치 = softmax(점수 ÷ √d_k), 출력 = 가중치로 섞은 value.**
</Callout>

</Section>

<Section id="why" level="intuition" title="왜 중요한가">

- Transformer, BERT, ViT, Swin 같은 모델이 모두 이 연산을 기본 부품으로 씁니다. <ConceptLink id="method:multi-head-attention">Multi-head attention</ConceptLink>은 이 연산을 여러 번 나란히 돌린 것이고, <ConceptLink id="method:transformer-encoder-layer">Transformer encoder layer</ConceptLink>의 첫 번째 부분입니다.
- 순환 신경망(RNN)은 단어를 하나씩 순서대로 처리해서 학습 예제 안에서 병렬화가 어렵습니다. Transformer는 이 순차 계산 문제를 해결 대상으로 삼았고<Cite claim="clm:transformer-addresses-sequential" loc="§1" />, self-attention 층은 모든 위치를 **일정한 횟수의 순차 연산**으로 연결합니다(RNN은 시퀀스 길이 n에 비례)<Cite claim="clm:transformer-mitigates-sequential" loc="Table 1" />.
- 이미지도 패치로 자르면 토큰처럼 다룰 수 있어서, 같은 연산이 비전으로 옮겨 갔습니다<Cite claim="clm:vit-adapts-transformer" loc="§3" />.

</Section>

<Section id="mechanism" level="fundamentals" title="핵심 작동 원리">

토큰이 n개, query·key 차원이 $d_k$, value 차원이 $d_v$라고 합시다. 모든 query를 행으로 쌓은 행렬을 $Q \in \mathbb{R}^{n \times d_k}$, key를 $K \in \mathbb{R}^{m \times d_k}$, value를 $V \in \mathbb{R}^{m \times d_v}$라고 하면(self-attention에서는 m = n), 연산은 네 단계입니다.

1. **점수**: $S = QK^\top \in \mathbb{R}^{n \times m}$. $S_{ij}$는 i번째 query와 j번째 key의 <ConceptLink id="concept:dot-product">dot product</ConceptLink>입니다.
2. **스케일**: $S / \sqrt{d_k}$.
3. **가중치**: 행마다 <ConceptLink id="concept:softmax">softmax</ConceptLink>를 취해 $A = \mathrm{softmax}(S/\sqrt{d_k})$. 각 행의 합은 1입니다.
4. **출력**: $O = AV \in \mathbb{R}^{n \times d_v}$. i번째 출력은 value 행들을 $A$의 i번째 행 비율로 섞은 것입니다.

논문은 이것을 "query와 모든 key의 dot product를 계산하고, 각각을 $\sqrt{d_k}$로 나눈 뒤, softmax로 value에 대한 가중치를 얻는다"고 설명하고 "Scaled Dot-Product Attention"이라고 부릅니다<Cite claim="clm:intro-sdpa" loc="§3.2.1" />.

<Section id="math" level="fundamentals" title="수학적 기초">

$$
\mathrm{Attention}(Q, K, V) = \mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V
$$

softmax는 벡터 $\mathbf{z}$를 $\mathrm{softmax}(\mathbf{z})_i = e^{z_i} / \sum_j e^{z_j}$로 바꿉니다. 두 가지 성질이 중요합니다.

- 결과는 모두 양수이고 합이 1입니다(가중치로 쓸 수 있다).
- 모든 성분에 같은 상수를 더해도 결과가 같습니다: $\mathrm{softmax}(\mathbf{z} + c) = \mathrm{softmax}(\mathbf{z})$. 구현에서 최댓값을 빼는 이유입니다.

<Level of="deep">

**왜 $\sqrt{d_k}$로 나누는가.** 논문은 "$d_k$가 크면 dot product의 크기가 커져 softmax를 기울기가 매우 작은 영역으로 밀어낸다고 추정한다"고 쓰고, 이를 막으려고 $1/\sqrt{d_k}$로 나눕니다<Cite src="src:arxiv:1706.03762v7" loc="§3.2.1" />. 각주는 그 크기를 이렇게 설명합니다<Cite src="src:arxiv:1706.03762v7" loc="각주 4" />. query와 key의 성분 $q_i, k_i$가 서로 독립이고 평균 0, 분산 1이라고 가정하면:

$$
\begin{aligned}
\mathbb{E}[q_i k_i] &= \mathbb{E}[q_i]\,\mathbb{E}[k_i] = 0 && \text{(독립)}\\
\mathrm{Var}(q_i k_i) &= \mathbb{E}[q_i^2]\,\mathbb{E}[k_i^2] - 0 = 1 && \text{(독립, 분산 1)}\\
\mathrm{Var}(\mathbf{q}\cdot\mathbf{k}) &= \sum_{i=1}^{d_k} \mathrm{Var}(q_i k_i) = d_k && \text{(항들이 독립이므로 분산의 합)}
\end{aligned}
$$

세 번째 줄은 <ConceptLink id="concept:variance-of-sum">독립 확률변수 합의 분산</ConceptLink> 성질입니다. 그래서 점수의 표준편차는 $\sqrt{d_k}$로 커집니다. $d_k = 64$이면 표준편차가 8이라, softmax 입력의 차이가 수십이 되고 출력은 거의 원-핫이 됩니다. $\sqrt{d_k}$로 나누면 분산이 다시 1이 됩니다. 이것은 softmax의 <ConceptLink id="concept:softmax-temperature">temperature</ConceptLink>를 $\sqrt{d_k}$로 두는 것과 같은 효과입니다.

이 설명은 **가정 아래의 근사 논증**입니다. 학습된 Q, K의 성분이 독립·분산 1이라는 보장은 없습니다. 논문도 "추정한다(We suspect)"고 썼습니다.

</Level>

<Section id="example" level="fundamentals" title="단계별 예제">

토큰 3개, $d_k = 2$인 작은 예를 손으로 계산해 봅니다. 설명을 위해 Q = K = V = X로 둡니다(실제 모델에서는 학습된 투영 행렬을 곱해 만듭니다).

$$
X = \begin{pmatrix} 1 & 0 \\ 0 & 1 \\ 1 & 1 \end{pmatrix}
$$

1. 점수 $S = XX^\top$: 첫 행은 $(1\cdot1+0\cdot0,\ 1\cdot0+0\cdot1,\ 1\cdot1+0\cdot1) = (1, 0, 1)$. 전체는 $\begin{pmatrix}1&0&1\\0&1&1\\1&1&2\end{pmatrix}$.
2. 스케일: $\sqrt{2} \approx 1.4142$로 나누면 첫 행은 $(0.7071, 0, 0.7071)$.
3. softmax: $e^{0.7071} \approx 2.0281$, $e^0 = 1$이므로 첫 행 가중치는 $(2.0281, 1, 2.0281) / 5.0562 \approx (0.401, 0.198, 0.401)$. 셋째 행은 $(0.248, 0.248, 0.503)$(반올림 때문에 합이 0.999로 보입니다).
4. 출력 첫 행: $0.401\cdot(1,0) + 0.198\cdot(0,1) + 0.401\cdot(1,1) \approx (0.802, 0.599)$.

스케일 없이 계산하면 첫 행 가중치는 $(0.422, 0.155, 0.422)$로 더 뾰족합니다. 이 예에서는 차이가 작지만, $d_k$가 커질수록 차이가 커집니다(시각적 설명의 Lab).

```python verify
import numpy as np

def softmax(z, axis=-1):
    z = z - z.max(axis=axis, keepdims=True)
    e = np.exp(z)
    return e / e.sum(axis=axis, keepdims=True)

X = np.array([[1.0, 0.0], [0.0, 1.0], [1.0, 1.0]])
S = X @ X.T
A = softmax(S / np.sqrt(2))
O = A @ X
assert np.allclose(S, [[1, 0, 1], [0, 1, 1], [1, 1, 2]])
assert np.allclose(A[0].round(3), [0.401, 0.198, 0.401])
assert np.allclose(A[2].round(3), [0.248, 0.248, 0.503])
assert np.allclose(O[0].round(3), [0.802, 0.599])
assert np.allclose(A.sum(axis=1), 1.0)
assert np.allclose(softmax(S)[0].round(3), [0.422, 0.155, 0.422])
print("example ok")
```

<Section id="code" level="fundamentals" title="구현">

numpy로 쓰면 몇 줄입니다. softmax에서 최댓값을 먼저 빼는 것은 결과를 바꾸지 않으면서(shift invariance) `exp`가 넘치는 것을 막기 위해서입니다.

```python verify
import numpy as np

def softmax(z, axis=-1):
    z = z - z.max(axis=axis, keepdims=True)   # 수치 안정성: 결과는 같다
    e = np.exp(z)
    return e / e.sum(axis=axis, keepdims=True)

def scaled_dot_product_attention(Q, K, V):
    d_k = Q.shape[-1]
    weights = softmax(Q @ K.T / np.sqrt(d_k))  # (n, m), 행 합 1
    return weights @ V, weights                # (n, d_v)

rng = np.random.default_rng(0)
Q, K, V = rng.standard_normal((4, 8)), rng.standard_normal((6, 8)), rng.standard_normal((6, 3))
out, w = scaled_dot_product_attention(Q, K, V)
assert out.shape == (4, 3) and w.shape == (4, 6)
assert np.allclose(w.sum(axis=1), 1.0)
# 큰 logit에서도 NaN이 나오지 않는다
assert np.all(np.isfinite(softmax(np.array([1000.0, 0.0]))))
# 분산 확인: 성분이 N(0, 1)이면 Var(q·k) ≈ d_k, 스케일 후 ≈ 1
for d_k in (4, 64, 512):
    q, k = rng.standard_normal((20000, d_k)), rng.standard_normal((20000, d_k))
    s = (q * k).sum(axis=1)
    assert abs(s.var() / d_k - 1) < 0.05
    assert abs((s / np.sqrt(d_k)).var() - 1) < 0.05
print("implementation ok")
```

<Section id="limitations" level="deep" title="한계와 트레이드오프">

- **계산·메모리가 토큰 수의 제곱**: self-attention 층의 계산량은 $O(n^2 \cdot d)$입니다<Cite src="src:arxiv:1706.03762v7" loc="Table 1" />. 고해상도 이미지처럼 토큰이 많으면 부담이 커지고, Swin Transformer는 이것을 해결 대상으로 삼아 창(window) 안에서만 attention을 계산합니다<Cite claim="clm:swin-addresses-quadratic" loc="§1, §3.2" />.
- **순서를 모른다**: 점수 계산에 위치 정보가 없어서, 토큰 순서를 바꿔도 각 출력은 같은 방식으로 섞입니다. 그래서 Transformer는 입력 embedding에 <ConceptLink id="method:positional-encoding">positional encoding</ConceptLink>을 더합니다<Cite src="src:arxiv:1706.03762v7" loc="§3.5" />.
- **포화**: 스케일이 맞지 않으면 softmax가 원-핫에 가까워져 기울기가 작아집니다(수학 절). $\sqrt{d_k}$ 스케일은 성분 분포에 대한 가정에 기댄 처방입니다.

</Section>

<Section id="history" level="deep" title="역사적 발전">

- **2014 — 정렬을 함께 배우는 번역(Bahdanau et al.)**: 인코더–디코더 번역에서 문장 전체를 고정 길이 벡터 하나로 압축하는 것이 병목이라고 보고, 디코더가 원문의 관련 위치를 부드럽게 찾게 했습니다<Cite claim="clm:intro-additive-attention" loc="§1, §3.1" />. 이 점수 함수는 작은 신경망(덧셈 꼴)이라 나중에 additive attention이라고 불립니다.
- **2017 — Transformer(Vaswani et al.)**: 점수를 dot product로 바꾸고 $1/\sqrt{d_k}$ 스케일을 더했습니다. 논문은 "dot-product attention은 스케일링 인자를 빼면 우리 알고리즘과 같다"고 밝힙니다<Cite claim="clm:intro-sdpa" loc="§3.2.1" />. 행렬 곱으로 구현할 수 있어 additive보다 실제로 빠르고 메모리를 덜 쓴다고 설명합니다.
- **2020 — ViT(Dosovitskiy et al.)**: 이미지를 16×16 패치로 잘라 토큰처럼 다루고, 원래 Transformer 설계를 최대한 그대로 따랐습니다<Cite claim="clm:vit-adapts-transformer" loc="§3" />.
- **2021 — Swin Transformer**: 전역 attention의 제곱 비용을 창 단위 attention으로 줄였습니다<Cite claim="clm:swin-addresses-quadratic" loc="§3.2" />.

</Section>
