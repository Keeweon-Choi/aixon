# 00. Product Brief — AIXON

> **AIXON**(AI + AXON, 구 가칭 Neural Atlas) — AI 연구 분야 전체를 잇는 Knowledge Graph와 개념별 교육 Wiki를 하나로 묶은 **Interactive AI Knowledge Atlas**. 브랜드 표시명은 바뀔 수 있으므로 코드·데이터의 도메인 식별자(엔티티 ID, 모듈·컴포넌트 이름)는 `aixon` 대신 기능명(`atlas`, `wiki`, `graph`)을 쓴다. 예외로 **배포·실행 설정**에는 프로젝트 이름을 둔다: 환경 변수 `AIXON_BUILD`·`AIXON_BASE`, 빌드·E2E의 기본 base 경로 `/aixon/`(Makefile의 `PUBLIC_BASE`·`E2E_BASE`, 실제 공개 값은 저장소 이름으로 정해짐, ADR-018), 공개 관문 산출 디렉터리 `.aixon/`. 이 이름들은 바뀌어도 데이터(YAML)의 ID에는 영향이 없다.
> 작성 2026-10-15 · 상태: v0.1 기준선 · 방향 수정 이력: 같은 날 "개인 학습 앱"(P0: 학습 경로·숙련도)에서 "Atlas + Wiki"(P0: 지도·교육 콘텐츠)로 바뀌었다(ADR-019).

---

## 1. 비전

AI 연구를 공부하는 사람이 **분야의 구조(무엇이 있고 어떻게 이어지는가)**와 **개별 개념의 이해(이것은 무엇이고 왜 이렇게 작동하는가)** 사이를 끊김 없이 오가게 한다. 지도에서 노드를 누르면 그 개념을 제대로 이해할 수 있는 교육 페이지로 가고, 페이지 안의 개념 링크는 다시 지도의 노드로 돌아간다. 모든 관계와 핵심 주장에는 원문 근거와 검증 상태가 붙는다.

## 2. 문제 분해

| 문제 | 근본 원인 | 지금의 해결 방법 | 한계 | AIXON 가설 | 구현 가능성 | 검증 방법 |
|---|---|---|---|---|---|---|
| **연구 탐색** (어떤 분야·문제가 있고 어떻게 이어지나) | 분야 지형이 논문 수만큼 빠르게 커지고, 분류 체계가 서비스마다 다르다 | Semantic Scholar·OpenAlex 주제 페이지, 서베이 논문, 강의 목차 | 주제 분류가 거칠거나(OpenAlex "Advanced Neural Network Applications"에 ViT·ResNet이 함께 들어감) 개념 단위가 아니다 | 사람이 큐레이션한 넓은 분류(Broad Coverage) + 깊이가 있는 곳 표시(Coverage) | 높음(편집 링크는 근거가 필요 없다) | 분야별 노드·Wiki 수, Coverage 화면에서 "빈 곳"을 찾는 데 걸리는 시간 |
| **연구 계보** (무엇이 무엇에서 나왔고 무엇을 개선했나) | 인용은 영향이 아니다. 논문은 계보를 문장으로만 남긴다 | Connected Papers·ResearchRabbit(유사도·인용 그래프), Litmaps(시간축), scite(인용 성격) | 논문 단위 그래프이고 "모델 X가 Y를 어떻게 바꿨나"(EXTENDS·ADAPTS·IMPROVES_ON)는 없다 | 모델·방법 단위의 **유형 있는 관계 + 원문 인용 + 조건** | 중간(큐레이션 비용이 든다) | 시드 Claim의 인용 원문 대조 통과율, 사람 검토 승인율 |
| **선수 지식 파악** (이걸 이해하려면 무엇이 필요한가) | 교재는 순서를, 논문은 전제를 생략한다 | Metacademy(2014, 보관됨), Math Academy(수학), 교재 목차 | AI 연구 개념과 논문에 연결된 최신 선수 그래프가 없다 | 정의식 근거(definitional dependency)로 검증한 **차원별 선수 관계**를 Wiki에 표시 | 중간 | 선수 Claim 중 정의식 근거 비율, 검토 반려율 |
| **개념 이해** (식이 왜 그런지) | 설명이 블로그·강의·논문에 흩어져 있고 수준이 다르다 | d2l.ai, 블로그, LLM 대화 | 근거가 불분명하거나(LLM) 단계적 깊이가 없다 | 직관 → 기초 → 심화 단계, 계산으로 확인한 예제, 원문 인용 | 높음(콘텐츠 작성 비용) | 문서별 검증 코드 통과, 사람 검토 체크리스트 |
| **지식 단편화** (배운 것이 다음 논문과 이어지지 않음) | 노트가 논문별로 따로 쌓인다 | Obsidian·Notion 노트 | 같은 개념을 매번 새로 설명 | 하나의 Canonical ID로 개념을 고정하고 모든 문서·관계가 그 ID를 가리킨다 | 높음 | 문서 사이 링크 수, 깨진 링크 0 |
| **개념적 이해의 검증** | 읽는 것과 아는 것은 다르다 | 퀴즈 앱, Anki | AI 연구 개념과 연결된 검증 문항·실험이 드물다 | Lab(예측 → 관찰 → 설명) + 확인 문제 | 중간 | Lab 수치가 독립 계산과 일치(E2E-2) |
| **학습자 상태 추정·장기 기억** | 개인 데이터가 없다 | Anki, Math Academy | — | **P2**(04 문서 설계 보존) | — | — |

## 3. 대상 사용자와 해야 할 일 (JTBD)

**1차 사용자**: AI 엔지니어·대학원생. 딥러닝 코드를 써 봤고(예: CV·엣지 배포), 논문을 읽다 개념이나 계보에서 막힌다. 첫 사용자는 프로젝트 소유자 본인이다.
**2차 사용자**(공개 사이트): AI 분야 지도를 찾는 학생·실무자. 로그인 없이 읽는다.

| JTBD | 상황 → 원하는 것 → 결과 |
|---|---|
| J1 지형 파악 | 새 분야(예: 3D 인지, 로봇 정책)를 보기 시작할 때 → 하위 분야·핵심 개념·대표 논문을 한 화면에서 보고 싶다 → 무엇부터 읽을지 정한다 |
| J2 계보 이해 | 어떤 모델(ViT)을 만났을 때 → 무엇에서 나왔고 무엇을 개선했는지 근거와 함께 보고 싶다 → 논문의 위치를 안다 |
| J3 개념 이해 | 수식(attention의 √d_k)에서 막혔을 때 → 직관부터 유도까지 단계적으로, 손계산과 실험으로 확인하고 싶다 → 자기 말로 설명할 수 있다 |
| J4 선수 지식 | 개념을 이해하는 데 무엇이 필요한지 모를 때 → 검증된 선수 개념 목록을 보고 싶다 → 빠진 것만 채운다 |
| J5 신뢰 | AI가 쓴 설명을 볼 때 → 무엇이 원문으로 확인되었고 무엇이 검토 전인지 알고 싶다 → 믿을 만큼만 믿는다 |

## 4. 핵심 가치 제안과 차별점

기존 서비스가 이미 잘하는 것은 차별점으로 내세우지 않는다(01 문서): 문헌 검색과 인용 그래프(Semantic Scholar, Connected Papers, ResearchRabbit, Litmaps), 인용 문맥·성격 라벨(Semantic Scholar, scite), 개념 선수 그래프와 학습 계획(Metacademy, Math Academy, ALEKS), 인터랙티브 설명(TensorFlow Playground, Transformer Explainer, Distill), 출처를 붙인 LLM 답변(Elicit, Consensus, NotebookLM).

AIXON이 결합하는 것:
1. **모델·방법 단위의 유형 있는 연구 계보**(EXTENDS·ADAPTS·IMPROVES_ON·MITIGATES) — 관계마다 원문 인용(특정 버전), 조건, 검증 상태, 사람 검토 상태가 붙는다. 그럴듯하지만 근거가 없는 관계는 rejected로 남긴다(예: "VGG EXTENDS AlexNet").
2. **같은 Canonical ID로 연결된 교육 Wiki** — 지도의 노드와 교육 페이지가 하나의 ID로 이어지고, 페이지 안의 수식·예제는 실행 가능한 검증 코드로 확인된다.
3. **AI 생성 콘텐츠와 검토된 콘텐츠의 명시적 구분** — 공개 사이트에는 사람이 승인한 것만 나간다(ADR-017).
4. **넓은 지도 + 깊이의 가시화** — AI 전체 분류를 넓게 깔고, 어디에 검증된 깊이가 있는지(Coverage)를 보여 준다.

## 5. MVP 범위 (v0.1) — 상세는 [07_MVP_ROADMAP.md](07_MVP_ROADMAP.md)

**P0**: AI 전체 분야 Knowledge Graph(넓은 분류 초안 + 검증된 CV 표현학습 시드), Interactive Atlas, Wiki 콘텐츠 모델과 렌더러, 대표 개념 교육 페이지(Scaled Dot-Product Attention), 수식·코드·다이어그램, Graph ↔ Wiki 이동, 검색, 근거·참고문헌, 검증된 시드 콘텐츠, GitHub Pages 배포 설정, 자동 검증 하네스.

**명시적 비목표(v0.1)**: 사용자 계정, 개인 숙련도·학습 경로·이력·복습(P2), 서버·DB·LLM 호출, 대규모 자동 수집, LLM이 만든 관계의 자동 승인, 외부 그림·문장 복사, 실제 배포(사용자 승인 전).

## 7. 원칙 (요약)

Correctness over Coverage — 단, 지도는 **넓게 먼저 깔고 미검증임을 표시**한다(Broad Coverage First, Selective Depth Second). Evidence over Plausibility. 연구 관계 ≠ 선수 관계. CITES ≠ 영향. 결정적 계산. 작은 검증된 그래프에서 시작. 필요가 생기기 전에는 복잡성을 들이지 않는다. 설명 가능성. 1인이 유지보수할 수 있는 구조. LLM은 진실의 원천이 아니다.
