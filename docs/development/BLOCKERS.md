> 마지막 갱신: 2026-10-15 14:3x(배포·GitHub Actions 반영). 해결되면 지우지 말고 "해결" 열을 채운다.

| ID | 무엇이 막혔나 | 왜 | 필요한 것 | 해결 |
|---|---|---|---|---|
| B-01 | GitHub Pages 실제 배포 | 외부 공개는 승인 필요(지침, ADR-018) | 저장소 이름·공개 여부·push 승인 | 해결(사용자 10-15): "그냥 배포해도 돼 클로드 표시는 상관없으. 사람이 학습할 수 있는 내용의 정합성만 확보되면 돼". 공개 저장소 `Keeweon-Choi/aixon`, 배포 완료 https://keeweon-choi.github.io/aixon/ (Pages run 38683822204 외) |
| B-02 | public 빌드에 담을 콘텐츠 | AI 생성 콘텐츠 자동 게시 금지(ADR-017). 지금 public 빌드는 승인된 Claim만 내보내고 Wiki는 "준비 중" | 사람 검토(시드 Claim, 대표 Wiki, atlas 요약) | 경로 변경(사용자 10-15): 사람 승인 대신, 근거가 실제 웹 출처인 독립 AI 검토자들(추론 능력 동급)의 교차 검증을 통과한 콘텐츠는 자동 게시해도 된다. LLM이 지어낸 내용은 안 되고 사람이 쓴 비유는 된다. 기준 `docs/verification/CROSS_REVIEW.md`, ADR-026. 사람 검토는 로컬 검수 화면(ADR-025)에서 선택. 사전 검수표(`review/first-release.yaml`)와 `review.py approve-batch`·`publish`는 이미 있다. 도구 구현 중, 게시 0건, 사람 승인 0건 |
| B-03 | 콘텐츠 라이선스 | 공개 전에 정해야 함 | 텍스트·코드·그림 라이선스 결정(예: CC BY 4.0 / MIT) | 해결(사용자 10-15): 텍스트·설명·그림 CC BY 4.0, 코드 MIT (`LICENSE`, `LICENSE-CONTENT.md`) |
| B-04 | `~/aixon`의 git 관리 | 자동 커밋 금지 | `git init` 여부, 원격 저장소 | 해결(사용자 10-15): `~/aixon`을 개발 이력 그대로 git 저장소로 만듦(정본) |
| B-05 | `~/aixon/ss_copilot.html` | 조사 에이전트 산물로 보이나 무관한 파일 삭제 금지(I-14) | 삭제 여부 | 해결(사용자 10-15): 삭제 |
| B-06 | 식별자 검증(arXiv) CI 단계 | 네트워크 필요, CI에서는 선택 단계 | 없음 | 해결(10-15): GitHub의 `verify-online.yml`(주 1회 + 수동). 첫 통과 실행 38686154873(인용 132 found + 경고 31, 식별자 67/67). 앞선 실행 38685394444·38685733040은 실패 후 수정(W106을 경고로, 증거 업로드 `if: always()`) |
| B-07 | 공개 저장소 정책 | 무료 GitHub Pages는 **공개 저장소**가 필요하다. 저장소가 공개되면 public 빌드의 승인 관문(ADR-021)과 무관하게 미검토 초안(`data/`·`src/content/`의 AI 생성 콘텐츠), `docs/`, git 이력이 모두 공개된다. 같은 이유로 `ss_copilot.html`(B-05, I-14)과 `study/`(별도 요청 산출물)도 공개 대상이 될 수 있다 | 사용자 결정. 선택지: (a) 비공개 저장소 + 유료 Pages, (b) `dist-public`만 받는 별도 공개 저장소(소스는 비공개 유지), (c) 공개 저장소를 받아들이되 초안을 명시적으로 표시하고 `ss_copilot.html`·`study/`를 제외 | 해결(사용자 10-15): (c) 공개 저장소로 배포 |
| B-08 | 공개 저장소의 커밋 이력 | 사용자 이름으로 공개할 저장소에는 Claude 표시를 넣지 않는다(사용자 규칙 10-12). 통합 저장소 `~/wt/aixon-base`의 지금까지 커밋 메시지에는 `Co-Authored-By: Claude …` 줄이 있다(10-15 11:4x부터는 넣지 않음). 이력 재작성은 승인 없이 하지 않는다 | 사용자 결정: 공개할 때 이력 없이 `~/aixon`(git 아님)에서 새 저장소를 만들거나, 이력 정리를 승인 | 해결(사용자 10-15): Claude 표시는 상관없음. 공동 작성자 줄을 받아들이고 이력을 다시 쓰지 않는다 |
